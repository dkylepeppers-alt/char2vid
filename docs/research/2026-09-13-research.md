# Research for char2vid

**Research date:** 2026-09-13 UTC. **Repository at inspection:** empty, public, default branch `main`.

The recommendation is an Android-first local media library plus a durable generation service. Zeemo supplies useful connected-workflow ideas; Reallusion supplies useful character preparation and reference-binding ideas. Nano-GPT supplies inference, not the app's visual character database or device storage.

## Evidence and coverage

- Retrieved all **123 documentation pages** listed in Nano-GPT's [documentation index](https://docs.nano-gpt.com/llms.txt), plus its [OpenAPI document](https://docs.nano-gpt.com/api-reference/openapi.json).
- Inventoried every indexed page. Examined the media, catalogs, authentication, jobs, billing, errors, and SDK material in detail. Peripheral integrations and account administration were screened for relevance, not runtime-tested.
- Made unauthenticated, read-only GET requests to seven live catalogs and three image endpoint-metadata URLs. Retrieved counts are API records, not promises of account access or successful generation.
- Inspected Zeemo's Canvas and Scene Director public pages in a browser, and Reallusion's public product page and manuals. No signed-in workspace or installed desktop/mobile application was tested.
- No paid inference, model training, voice cloning, account registration, or deployment was performed.

The [resource inventory](nanogpt-resource-inventory.md) and [discovery snapshot](discovery-snapshot.json) preserve scope, URLs, counts, and hashes without copying the documentation wholesale.

### Differences between examples and live metadata

1. **Parameter shapes differ.** Image responses used fields such as `resolutions`, `max_output_images`, and `max_input_images`; video responses used nested `supported_parameters.parameters` and `defaults`, with `select`, `switch`, and `number` controls. Documentation examples also show `enum` and `range`. A single assumed JSON schema will fail. [Image metadata reference](https://docs.nano-gpt.com/api-reference/endpoint/image-api-model-endpoints), [live video catalog](https://nano-gpt.com/api/v1/video-models?detailed=true).
2. **Capabilities can conflict.** The inspected `bytedance/seedance-2.5` record advertised `audio_generation: false` while presenting a `generate_audio` switch defaulting to true. Neither boolean alone is sufficient to certify audio support. Preserve the conflict and verify the exact route before enabling that option. [Live video catalog](https://nano-gpt.com/api/v1/video-models?detailed=true).
3. **Resolution labels are not always pixel dimensions.** The inspected Seedream 5.0 Pro metadata mixed aspect ratios with `1k`/`2k` under `resolutions`. Do not turn these labels into guessed output dimensions. Its endpoint described ten image inputs and a provider limit of 10 MiB per input, tighter than the route limit of 30 MiB. [Observed endpoint metadata](https://nano-gpt.com/api/v1/images/models/bytedance/seedream-v5.0-pro/endpoints).
4. **Model IDs are opaque.** Slash-containing IDs have returned endpoint paths; use those paths after validating the origin. Several records share display names. Preserve exact IDs and operation variants instead of merging by name. [Image catalog reference](https://docs.nano-gpt.com/api-reference/endpoint/image-api-models).
5. **The OpenAPI file is incomplete relative to the index.** It had 60 path entries and omitted newer normalized image/catalog surfaces. Some path objects also override the server base. Generate types selectively; do not generate the whole client from this one file without corrections. [OpenAPI](https://docs.nano-gpt.com/api-reference/openapi.json).

### Resources that should not be mistaken for missing studio features

- **Characters and character-models are chat personas**, with system prompts and base text models. They do not provide a portable visual actor, trained likeness, or video identity token. [Characters](https://docs.nano-gpt.com/api-reference/endpoint/characters), [character-models](https://docs.nano-gpt.com/api-reference/endpoint/character-models).
- The index exposes moderation, NSFW classification, AI-text detection, reasoning controls, caching, provider routing, memory, TEE verification, evals, team administration, key management, partner auth, payments, and integration guides. Their presence is recorded in the inventory; it does not make them required app features.
- The linked TypeScript client is explicitly unofficial and describes an inferred OpenAPI basis. Prefer a small typed transport with validated fixtures for this changing media surface. [TypeScript library](https://docs.nano-gpt.com/api-reference/miscellaneous/typescript).

## Uncertainties with concrete resolutions

| Finding | Required design response |
|---|---|
| Video prose uses nested uppercase `data.status`; embedded schema uses flat lowercase `status` and `videoUrl`. | Support both as distinct validated response variants; capture real responses before certifying the adapter. [Status reference](https://docs.nano-gpt.com/api-reference/endpoint/video-status-unified). |
| Video guide caps inline uploads at 4 MB; endpoint prose recommends base64 for larger/private assets. | Treat the size conflict as unresolved; stage large inputs at short-lived HTTPS URLs and record encoded request limits in route contracts. [Guide](https://docs.nano-gpt.com/api-reference/video-generation), [endpoint](https://docs.nano-gpt.com/api-reference/endpoint/video-generation). |
| No general external-client visual-character registration, universal media upload, media-job idempotency, or media cancellation/webhook contract was established. | App-owned characters, temporary reference service, durable local receipts, and explicit unknown-submission states. Do not call undocumented website attachment routes. |
| Output URLs can expire; normalized image response details are underspecified. | Download immediately into service staging and then local storage; verify envelopes, file signatures, dimensions, duration, and non-empty outputs. [Image compatibility response](https://docs.nano-gpt.com/api-reference/endpoint/image-generation-openai). |
| Catalog visibility is not credential validation. Invalid credentials can still return public models. | Validate credentials with an authenticated read; annotate eligibility separately from discovery. [Authentication](https://docs.nano-gpt.com/authentication). |
| OAuth documents HTTPS/explicit-port loopback redirects, origin-bound keys, and no refresh/revocation endpoint. | Start with a manually supplied app-specific Nano-GPT key; integrate OAuth later through a registered HTTPS callback. Do not assume a custom Android URI scheme is accepted. [OAuth PKCE](https://docs.nano-gpt.com/api-reference/miscellaneous/oauth-pkce). |

## Android and browser constraints

Android app-specific files and SQLite support the private working library; app-specific files are removed on uninstall. Export user-visible media through MediaStore and documents/backups through the Storage Access Framework. Import selected media with the system Photo Picker and copy it into the working library. [Storage overview](https://developer.android.com/training/data-storage), [Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker), [document access](https://developer.android.com/training/data-storage/shared/documents-files).

Browser OPFS is origin-private storage, not a user-visible folder. Browser data remains subject to quota and persistence behavior; request persistence, show storage state, and provide backups. [OPFS](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system), [quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

Capacitor currently documents version 8 and Node 22+. File transfer has a separate official plugin; `Filesystem.downloadFile` is deprecated. Large media should travel through file/stream APIs, not repeated base64 strings across the WebView bridge. [Environment](https://capacitorjs.com/docs/getting-started/environment-setup), [Filesystem](https://capacitorjs.com/docs/apis/filesystem), [File Transfer](https://capacitorjs.com/docs/apis/file-transfer).

WorkManager scheduling depends on OS constraints, so it cannot promise uninterrupted polling or an exact completion time. Use the service for generation monitoring and native background work for eventual transfer/reconciliation. Android Media3 provides a basis for trimming, effects, and multi-asset composition; verify the actual export subset on devices. [WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started), [Transformer](https://developer.android.com/media/media3/transformer), [multi-asset editing](https://developer.android.com/media/media3/transformer/multi-asset).
